# Портфолио-лендинг с тремя кейсами

Статическая страница, один файл, без сборки и зависимостей. Открывается двойным кликом.

- `index.html` - вся страница (стили внутри, шрифты системные, интернет не нужен)
- `assets/` - реальные ассеты: 4 кадра из демо-записи донатов и сам ролик 17.4 с
- `preview/desktop.png`, `preview/mobile.png` - полные скриншоты рендера (1280 и 390 px)
- `verify.js` - проверка без глаз: переполнение по ширине, битые картинки, видео, мёртвые якоря, ошибки консоли

## Как посмотреть

```
open ~/Documents/Portfolio/landing/index.html
```

Или проверить машиной:

```
cd ~/Documents/Portfolio/landing && node verify.js
```

Ожидаемый финал - `RESULT: clean`. Проверка гоняет два вьюпорта (1280x900 и 390x844)
через headless Chrome и CDP.

## Как опубликовать (делает Макс, это публикация от его имени)

Публичной страницы на `maxpol-ph.github.io` пока нет (корень отдаёт 404), есть только `/donate/`.
Вариант А, отдельный репозиторий под портфолио:

```
cd ~/Documents/Portfolio/landing
git init
git add index.html assets preview
git commit -m "Portfolio landing: three cases"
git branch -M main
git remote add origin https://github.com/maxpol-ph/portfolio.git
git push -u origin main
```

Затем в GitHub: Settings -> Pages -> Source: Deploy from a branch -> main / root.
Адрес будет `https://maxpol-ph.github.io/portfolio/`.

Вариант Б, без нового репозитория: положить в уже существующий `donate` как `/work/index.html`
(тогда ссылка `https://maxpol-ph.github.io/donate/work/`). Минус - портфолио живёт внутри
платёжной страницы, это путает клиента.

Вариант В: свой домен, если он появится. Тогда `CNAME` в корень репозитория.

Чего в репозиторий НЕ кладём: `.DS_Store`, `node_modules`, ничего из `recording/`.
